Privacy policy

Last updated: 29 September 2026

Scope and current status

personal-health is a personal project maintained by michael-bill for accessing the account owner's Fitbit data through the Google Health API. This public website documents the project. The MCP software is in early development and is not yet implemented in this repository. The connection practices below describe the intended scope of that software; this policy must be updated if its implementation changes those practices.

This public website

This website contains static information pages. It does not request Google authorization, read health records, accept credentials, or use application analytics, advertising scripts or application cookies. It is hosted by GitHub Pages. GitHub processes hosting information, including visitors' IP addresses, as described in the GitHub Privacy Statement.

Google data requested by the connection

Only the categories explicitly authorized by the account owner may be accessed:

  • Activity, fitness and workout records.
  • Health metrics and measurements, such as available heart rate and related measurements.
  • Sleep records.
  • Profile information, including age when available.
  • Account settings, such as time zone and preferred measurement units.
  • Nutrition and hydration logs.
  • GPS locations recorded during exercise.

The connection requests read-only Google Health permissions. It does not request access to Gmail, Drive, contacts or other unrelated Google services.

Purpose and sharing

Health data is used to retrieve the owner's records and support the owner's personal review and requested analysis. This project does not sell that data or use it for advertising. Its use of information received from Google APIs must adhere to the Google API Services User Data Policy, including the Limited Use requirements, and the applicable Google Health API policies.

If the owner connects an MCP client or AI assistant, the records requested through that connection may be transmitted to that client and its configured model provider. That provider's data handling and retention settings apply. The owner must choose and configure these services before sharing health data. The project is not intended to use Google user data to train general-purpose AI models.

Storage and credentials

The software is intended to run on the owner's computer or a server they control. Any retained health records, OAuth client credentials and tokens must be stored in private storage on that installation, outside the public website and public repository. Google receives credentials and tokens as required for authorization and API access. Secrets must not be exposed in assistant responses, screenshots, public files or application logs.

Retention, deletion and revocation

The owner controls retention on their installation and can delete locally stored records and credentials. Access to Google data can be revoked at Google Account connections. Revocation stops further authorized API access; it does not delete previously exported records or copies already sent to a separately configured provider. Those copies must be deleted from the relevant installation or service.

Contact and changes

Questions about this project can be raised through GitHub issues. Public issues must not contain health information or credentials. Policy changes will be published on this page with an updated date.
